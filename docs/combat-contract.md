# Combat integration contract v2

Task and discussion: [#6](https://github.com/Risxhb/collab/issues/6). Session owner: [#7](https://github.com/Risxhb/collab/issues/7). Encounter owner: [#8](https://github.com/Risxhb/collab/issues/8).

`game/core/combat_simulation.gd` is a node-free `RefCounted`. Construct it, then call `step(commands)` once per authoritative 1/60s tick. Commands map stable integer actor IDs to `{move: Vector2, basic: bool, technique: bool, signature: bool, guard: bool}`. Only configured IDs are consumed; unknown IDs are ignored and missing commands are neutral. Movement is clamped to unit length; non-finite movement becomes zero. Network decoding, payload types, ownership, rate limits and sender validation belong to the session layer before this API is called.

`configure_roster(entries: Array) -> bool` replaces the whole roster and resets the attempt using the current seed. Entries contain a positive integer `player_id`, `class_id` (currently only `vanguard`, also the default), and an optional `build` array (default empty). IDs must be unique; counts 1–8 are accepted. Invalid input returns false without changing state, generation or configuration. Input is deep-copied and sorted by player ID, so caller order does not change processing order or spawn slots. Build entries are opaque saved configuration; no upgrade effects or transport validation are implemented. Do not edit the public roster/actor dictionaries from session or encounter code.

`actors[id]` holds each actor's independent transient state and copied class/build configuration. `player` aliases the lowest-ID actor for compatibility with the solo view, which still controls ID 1 and renders only that actor. It is not a multiplayer view. Spawns occupy a fixed four-column grid within the arena; boss health/damage and demo timings are not party-scaled. The demo aims at the lowest-ID living actor.

Ordering: increment tick; process living actors by ascending stable ID (move, activate eligible guard, resolve one eligible offensive action); check victory; schedule hazards; update all hazard anchors and locks; resolve due hazards in insertion order for living actors by ascending ID; check party defeat. Each actor has its own offensive cadence, resources, cooldowns, guard and immunity. Actors processed after a lethal boss hit still move/guard but do not spend offensive cooldowns. A victory clears pending hazards and ends the attempt before that tick's hazard resolution. Knocked-out actors cannot move, attack, guard or receive further mechanic resolutions; defeat requires all actors to be knocked out. Defeat/victory freeze subsequent steps. All end ticks are exclusive (`tick < end_tick`).

`reset(seed_value = 1)` restores tick, RNG, every actor's spawn/health/resource/cooldowns/guard/immunity, boss health, active hazards, hazard IDs, event log and outcome. It preserves roster IDs, class/build configuration and the encounter provider. Providers must be stateless functions of tick/simulation/seed or use simulation-owned state that reset explicitly restores; do not keep a private clock/RNG in a scene node.

Set `encounter_provider` to a `Callable(tick: int, context: Dictionary) -> Array[Dictionary]` to replace the demo scheduler. Context is a detached snapshot plus `phase: scheduling`; its `roster` contains `player_id`, `class_id`, `build`, and `active` (health above zero). Modifying it cannot mutate authoritative actors or configuration. Return only newly warned hazards for that tick, using unique IDs within an attempt. Do not resubmit active hazards. Definitions are admitted through `queue_hazard(definition) -> bool`, deep-copied, then owned until resolution/cancellation. Invalid provider definitions are skipped; validate authored data before binding it. Provider context precedes this tick's anchor update; do not use its previous hazard geometry as the current tick's final lock position.

`queue_hazard` is also available to trusted local callers at the current simulation tick. Admission rejects ended attempts, reused/nonpositive/noninteger IDs, missing names, unknown shapes/anchors/components, nonfinite geometry, invalid radii/angles, warning ticks unequal to the current tick, and invalid lock/resolve ordering. Rejection leaves state unchanged. IDs remain reserved after resolution or cancellation until reset. This is authored-data checking, not a network decoder or a full encounter/reachability validator. Use this entry point rather than appending to the public hazards array.

Outside `step`, snapshot `tick` is the last completed simulation step. The provider runs during the current step after movement/offense, so its context `tick` is the in-progress scheduling tick. Reset increments `generation` even when seed/tick return to their initial values. Transport must match both session identity and generation before accepting feedback; event IDs restart within each generation. The session input envelope will carry a sequence, target tick and processed-sequence acknowledgment. Peer IDs must not become stable player IDs. These delivery/envelope features are session responsibilities, not implemented in the solo view.

Hazard fields:

| Field | Meaning |
|---|---|
| `id`, `name` | Stable attempt-local integer ID and human attack name |
| `kind` | `cone` or `donut`; add other shapes through a shared geometry change |
| `origin` | `Vector2` in arena coordinates |
| `direction`, `half_angle` | Cone direction and half-width in radians |
| `radius`, `inner_radius` | Outer radius; donut hole radius |
| `warning_tick`, `resolve_tick` | Integer timestamps; resolve must follow warning |
| `anchor` | `fixed` (default), `follow_until_lock`, or `snapshot_at_lock` |
| `anchor_component` | `origin` (default) or `direction` (cones only) |
| `target_player_id` | Required living roster ID for a nonfixed anchor |
| `lock_tick` | Defaults to warning; `warning_tick <= lock_tick < resolve_tick`; fixed anchors require lock equal to warning |
| `locked` | Simulation-owned boolean; authored values are overwritten |

`fixed` geometry is locked at admission. `follow_until_lock` samples the target immediately at admission and after movement on each tick through the lock tick, inclusive. `snapshot_at_lock` displays the authored origin/direction until the lock tick, then samples once. With `anchor_component: origin`, sampling replaces the origin with the target center and preserves direction. With `direction`, the authored origin stays fixed and the cone aims from there to the target; if the target coincides with the origin, retain the previous direction. Lock on the warning tick samples immediately, including a trusted queue call at tick zero. After lock, neither origin nor direction tracks the target. The solo renderer labels warnings TRACKING, PENDING LOCK or LOCKED using this state. Snapshot-at-lock's initial footprint is provisional, not a promise of a safe resolve position.

At anchor update, an unlocked warning whose target is unavailable is cancelled, emitting one `assignment_changed` event with `attack_id`, `attack_name`, `old_player_id`, `new_player_id: 0`, `cancelled: true`, `reason: target_unavailable`, tick and standard event identity. Locked hazards have become world geometry and persist after target knockout. All anchors update before damage: a knockout caused during resolution affects unlocked targeting on the next tick. This implements a cancellation fallback; provider-selected reassignment and disconnect APIs remain deferred.

`game/combat/hazard_geometry.gd` is the source for collision and visual shapes. Boundaries count as dangerous, with a one-microradian tolerance for float32 angular rounding. Collision uses the actor center. Curves are tessellated for drawing; collision uses analytic radii/angles. Both rendering and collision consume the simulation's updated origin/direction; the demo still locks its cone/donut when warned.

Resolved events include `schema_version`, `generation`, monotonic attempt-local `event_id`, affected `player_id`, `type: mechanic_resolved`, `tick`, `attack_id`, `attack_name`, `position` as `[x,y]`, `required_behavior`, `outcome` (`avoided`, `guarded`, `immune`, `hit`), `guarded`, and `mechanic_failed`. Anchor provenance includes `anchor`, `target_player_id` (default 0), `lock_tick`, `hazard_origin` as `[x,y]`, and `hazard_direction`. `source_attack_id` defaults to 0; full Echo retention/replay is not implemented. Guard can prevent damage while `mechanic_failed` stays true. The log retains the latest 128 records of all event types, not just the last step. Consumers must dispatch by `type`; assignment events have no damage outcome or affected `player_id`. Clients must deduplicate on generation/event ID; the session layer still needs reliable delivery/acknowledgment or gap recovery before event-dependent multiplayer feedback is accepted.

`snapshot()` returns a detached dictionary: `schema_version: 2`, `generation`, `tick`, `seed`, `actors`, `roster`, `boss`, `hazards`, `outcome`, `events`. Actors and roster are sorted by stable ID; actor positions and hazard origins become numeric arrays. Actors expose cooldown ready ticks and defensive end ticks. Both event types also use schema version 2. The snapshot is diagnostic/export only; no import, reconciliation or stable transport encoding exists. The snapshot omits internal RNG state, so it is not an arbitrary-tick save/checkpoint. Rehearsal phase restore must add full RNG/provider state later.

The local prototype intentionally repeats every held action when eligible. For network integration the agreed direction is held Basic plus consumed press requests for Technique/Signature/Guard, deduplicated by input sequence; this requires changing the view and simulation together before network binding. Do not resend an old press as a new command.

Accepted next-contract requirements from #7/#8 (not implemented here): independent encounter-targeting RNG; shared geometry/count evaluation of avoid/stack/spread/guard requirements; provider-selected assignment reassignment and disconnect handling. Disconnect mutation/reconnection APIs are not implemented; configure_roster starts a new attempt and must not be used to remove a participant mid-fight. Two party-size tiers with explicit count parameters remain required. These changes will be implemented in the shared core before encounters or session code bind to them. No encounter script should simulate these rules privately.

Ownership: foundation owns shared core/combat/actors/UI and root project wiring; networking owns `game/network/`; encounter authoring owns `game/encounters/` and `game/data/encounters/`. Ask the foundation owner for shared changes rather than copying simulation/geometry into another lane.
